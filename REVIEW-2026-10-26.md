## Details

### seo-utils 3.0.0

**SEO-1. Sitemap noIndex reads only the first page.** `src/bilingualSitemap.ts:153` requests `pagination[pageSize]=500` once and never follows `meta.pagination.pageCount`. Strapi also caps `pageSize` at its `api.rest.maxLimit`, often 100; need to check each site's Strapi config. A collection with more rows than the cap keeps its later `noIndex` pages in the sitemap.
Fix: loop pages until `page >= pageCount`. When `meta` is absent, process only the first page: the existing fixtures omit it (`sitemapExplicitBase.test.ts:29`). Stop on a failed or malformed page. Add capped-page, multi-page and later-page-failure cases for v4 and v5. Single types are not paginated.

**SEO-2. Homepage guard uses raw strings.** `src/canonical.ts:90`. `https://SITE.test/` on a sub-path is accepted, though the README (line 877) says a sub-path may not claim the home page.
Fix: compare `new URL(...)` normalised forms, as the host check above already does. `src/seo.ts:256` has a second raw comparison under the default policy that needs the same fix. Keep `"passes a CMS canonical through unchecked"` (`mainEntryUnchanged.test.ts:49`) green.

**SEO-3. Image URL join.** `src/seo.ts:230`: `startsWith("http") ? url : baseUrl + url`. Strapi usually returns `/uploads/…` or an absolute URL, so this is low.
Fix: `new URL(url, baseUrl + "/")` inside a try, accepting only http(s); a malformed URL must not start throwing. `src/bilingual.ts:204` has the same join and needs the same fix. This knowingly diverges from the legacy oracle (`__fixtures__/legacy-seo-mitt.js:75`), so record the changed cases.

**SEO-5. Encoded sitemap paths.** `src/bilingualSitemap.ts:122-129` builds the set from raw slugs. `normalizeSitemapPath` (`src/sitemap.ts:33`) does not decode. If next-sitemap passes `/ar/%D9%85…` to `transform`, an Arabic `noIndex` page stays in the sitemap. That matters for the en/ar sites. Need to check what next-sitemap actually passes for a non-ASCII route.
Fix: add both the raw and the `encodeURI` form of each path to the set. That leaves `normalizeSitemapPath` unchanged.

**SEO-6. `metaRobots: "none"`.** `src/noIndex.ts:51` tests only `/noindex/`, so `"none"` (noindex + nofollow) renders as indexed, while `inspectExportedHtml` treats it as noindex. The README table (line ~858) documents only `noindex`, so this is a doc change too.
Fix: match `noindex` or the token `none`; `none` means `follow: false`.

**SEO-7.** The route is concatenated unencoded at `seo.ts:245`, `bilingual.ts:278,307`, `localized.ts:146,203` and `bilingualSitemap.ts:226`. Reproduced: `products/a#b` gives the canonical `https://site.test/products/a#b/`, whose pathname is `/products/a`. Strapi slugs rarely hold `#` or `?`, so defer.

**SEO-10.** `localized.ts:193,225` and `bilingual.ts:281,307` build hreflang from the computed route even when a CMS canonical points elsewhere, so the canonical and the hreflang cluster disagree. Google expects hreflang to point at canonical URLs. The fix (suppress the cluster on a page that canonicalises elsewhere) removes hreflang tags from those pages. **You decide.**

**SEO-8..16 (others).** All verified by reading. SEO-14 and SEO-15 also reproduced: `{ Name: "Alice", Title: " " }` gives `"Alice —"`, and a CRLF robots.txt comes back unchanged. Codex checked JSON-LD and found no new issue: `<` is escaped, and U+2028/2029 round-trip.

`PLAN-seo-utils-3.0.1.md` is drafted and held until you approve its scope.

**SEO-4. Comments and scripts in `<head>`.** `src/buildNoIndex.ts:97,114`. A Next export does not emit commented meta tags. Skip.

### link-utils 1.0.0

**LINK-1. Unsafe schemes.** `src/resolveHref.ts:40` treats anything containing `://` as external and returns it unchanged. `javascript://%0Aalert(1)` and `javascript:alert(1);void("https://x")` come out as live hrefs. A plain `javascript:alert(1)` becomes `/javascript:alert(1)` and is harmless. text-utils already blocks these schemes (`parseMarkdownLinks.ts:22-30`), so the two packages disagree.
Fix: copy text-utils' `UNSAFE_SCHEME` and `IGNORED_IN_SCHEME` check, then resolve the href to a safe fallback. Decide which: `"/"` (the same as an empty href) or `"#"`.

**LINK-2.** `src/resolveHref.ts:37,46` regexes lack the `i` flag. `MAILTO:a@b.com` → `/MAILTO:a@b.com`, and `HTTPS://x` stays `_self` with no `rel`.

**LINK-3.** `src/resolveHref.ts:30` turns `/search?next=//cdn/a//b` into `/search?next=/cdn/a/b`. Limit the cleanup to the path part of internal hrefs.

**LINK-4.** `src/externalUrl.ts:39` turns `//example.com/path?x=1` into `//example.com/path/?x=1`. The README says external URLs are left alone.

Note: `resolveHref` was "extracted verbatim" from the sites' NavigationLink. These fixes knowingly change that behaviour, for bad inputs only.

The Codex challenge round added constraints:
- README lines 121-125 promise that any value containing `://`, or starting with `data:`, is left untouched. Blocking `javascript:` therefore withdraws a documented behaviour, and the README must say so. Block only `javascript:` and `vbscript:`, and keep `data:`: browsers already refuse top-level `data:` navigation.
- Make the `/https://` repair at line 25 case-insensitive too.
- Keep the `/sectors//food` → `/sectors/food` test (`link-utils.test.ts:129`).

### text-utils 1.1.0

**TEXT-1. Key collision.** `src/MarkdownLinks.tsx:55,57`: text tokens are keyed by index, links by `offset`, and both become strings. `"ab[x](/x)tail"` gives keys `0, 2, 2`. React warns, and after an update an old `<a>` can stay in the DOM.
Fix: `key={`t${i}`}` and `key={`l${token.offset}`}`.

**TEXT-2. Quadratic regex.** `src/parseMarkdownLinks.ts:18`. Measured locally: 10k `[` ≈ 50 ms, 40k ≈ 766 ms. Editor input only, so it's low, but `[^\]\n]` or a short linear scanner is a cheap fix.

**FORM-4.** `:82` clears the tooltip only for `name="email"` or `id="email"`, but the field may have been found by `type="email"`. Fix: `e.target === emailInput`.

**FORM-5.** `src/form-utils.ts:129`: `rect.top` is already viewport-relative, so the tooltip always flips below on a scrolled page.

**FORM-6.** `src/recaptcha.ts:9` matches `/f/embed.php` anywhere, including visible text. Fix the code (match a `<script src>`) or the README line 298.

## Codex challenge round

Codex reviewed this file and agreed with every severity. It disagreed on these points:

- **Versioning.** Codex reads SKILL.md's rule ("every existing export … behaves the same for current callers; otherwise … major") as making every behaviour-changing fix major. Claude disagrees. Repo precedent ships bug fixes as patches: form-utils 1.3.1 "tighten the embed check", 1.3.2 Wisent detection, next-preview-core 1.1.1/1.1.2 refetch changes. A fix that restores documented behaviour is a patch. Withdrawing documented behaviour (LINK-1 `://` passthrough) is the exception that needs your call. **You decide.**
- **AF-5: fix, not skip.** The accessor contract allows offset timestamps, and date-utils itself tests `+03:00` strings. Agreed: it's cheap, but it isn't in the plans.
- **SEO-4: fix, not skip.** Absence from the current fixtures proves nothing. It's cheap, and it can go in with the held seo-utils work.
- **DATE-2:** throw `RangeError`, as the README policy says. Rendering moment's default format would be timezone-sensitive. **DATE-3:** document the exception to "byte-identical".
- **FORM-2:** a CMS editor isn't needed for this one. Any window with a handle to the page can post. Still defer, as an opt-in minor.
- **I18N-2..4:** the deferred fixes are incomplete. They don't define what happens with no enabled locale, or with malformed escapes, and seo-utils has no `localeFromPath`; the comparison is at `localized.ts:166`.

Plan fixes already applied to the PLAN files before npm-agent started:
- NPC-2: the fetcher must return `null` for no data; `{ data: null }` is truthy and would hide "Page not found!".
- NPC-1: add a package-resolution check in both module modes.
- FORM-3: don't stack readiness polls.
- FORM-6: regex only, server-safe; keep the single-quote and custom-domain tests.
- AF-2: also fix the JSDoc.
- I18N-1: no origin check.
- SOC-1: keep the existing extraction tests.

Open decisions:
